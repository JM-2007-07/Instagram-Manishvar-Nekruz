# Истории (stories) — журнал действий

> Статус: ✅ принято (2026-10-21). Истории только **добавляются**; существующие не переписываются.

История — отдельный файл о **значимом действии** в проекте: что попросили, что сделали, почему так, какие файлы
изменились, чем проверили, что не получилось и что дальше. Вместе истории — полная хроника проекта: любой
человек или ИИ может восстановить, как проект пришёл к текущему состоянию, не видя прошлых разговоров.

## Чем история отличается от других записей

| Запись | Отвечает на вопрос |
|---|---|
| [STATUS.md](../STATUS.md) | что происходит **сейчас**; §7 — оглавление историй |
| **История** | что и **как** сделали в конкретный момент, с причинами, проверками и проблемами |
| [ADR](../decisions/README.md) | **почему** принято архитектурное решение |
| Коммит Git | **какие строки** изменились |

## Когда создавать

Создаётся новая история, если в репозитории изменилось что-то значимое:

- завершена задача `Tx.y` или её крупный шаг (backend готов, frontend готов);
- сессия работы изменила файлы (даже если задача не закончена — тогда «что дальше» особенно важно);
- изменён API-контракт, `schema.prisma`, общие файлы, инфраструктура, процесс работы;
- закрыт открытый вопрос `Qn` или принят ADR;
- произошло что-то важное: неудачная миграция, откат, найденная уязвимость, конфликт слияния.

Не нужна для: исправления опечатки, форматирования, правки одной ссылки — достаточно коммита.

Историю создаёт тот, кто выполнял работу: студент, оркестратор Claude Code или агент `docs-keeper`
по фактам от оркестратора. История коммитится **в том же коммите**, что и работа.

## Имя файла

```
ГГГГ-ММ-ДД_ЧЧММ_<кратко-на-английском>.md
2026-10-21_1430_posts-create-endpoint.md
```

- Дата и время — **местное время начала работы** (UTC+05:00); по ним файлы сортируются хронологически.
- Краткое описание — kebab-case на английском, 2–5 слов.
- Если в одну минуту две истории — добавьте суффикс `-2`.

## Правила

1. **Не переписывать.** Ошибку в истории исправляют новой историей со ссылкой на старую. Допускается только
   добавить в конец раздел `## Дополнение (ГГГГ-ММ-ДД ЧЧ:ММ)` — например, номер PR, появившийся позже.
2. **Только факты.** Команды и проверки — только реально выполненные, с результатом. Не проверено — так и написать (⚠️).
3. **Ссылки вместо копий.** На задачу (`T2.3`), вопросы (`Q10`), ADR, спецификации, коммиты.
4. **Коротко.** Обычно 20–60 строк. Подробности кода — в коде и коммитах.
5. **Оглавление.** Каждая новая история добавляется строкой **сверху** в [STATUS.md §7](../STATUS.md#7-истории).
6. Истории не конфликтуют при слиянии: каждый пишет свои файлы. Конфликт возможен только в строках оглавления —
   сохраняются обе.

```markdown
| | |
|---|---|
| Задача | T… / — |
| Фаза | … |
| Автор | Студент A/B · или Claude Code (оркестратор, модель) по запросу … |

| Ветка, коммиты | `<branch>` · коммит с этой историей |

## Запрос

- …

- ⚠️ не проверено: …

- …

## Что дальше
- …
```
