# Хэштеги и упоминания

> Функции F-TAG-*, F-SRC-04 · API [endpoints/tags.md](../api/endpoints/tags.md), подсказки — [search.md](../api/endpoints/search.md).

## Назначение
`#хэштеги` и `@упоминания` в подписях, комментариях, bio и историях: ссылки, индекс хэштегов, страницы хэштегов,
уведомления упомянутым, подсказки при вводе.

## Пользовательские сценарии
1. В тексте `#закат` становится ссылкой на `/explore/tags/закат/`, `@user` — на `/user/` (если аккаунт существует и виден).
2. Ввод `#` или `@` в поле подписи/комментария → выпадающий список вариантов (хэштеги с числом публикаций; аккаунты).
3. Страница хэштега: заголовок `#tag`, «N публикаций», сетка «Лучшие» / «Недавние».
4. Упомянутый получает уведомление «user упомянул(а) вас в комментарии / публикации / истории».

## Данные
`Hashtag`, `PostHashtag`, `PostMention`, `CommentMention` — [DATA_MODEL.md «Хэштеги»](../database/DATA_MODEL.md#хэштеги-tags).

## Права доступа
Страница хэштега — все вошедшие, только видимые публикации. Упоминание создаёт уведомление, только если
`mentionsFrom` упомянутого это разрешает; иначе текст остаётся обычным.

## Валидация 📝
Хэштег: буквы (Unicode), цифры, `_`, ≤ 100 символов, ≤ 30 в подписи. Упоминание: допустимое имя пользователя, ≤ 20 в подписи, ≤ 5 в комментарии.

## Ошибки и пустые состояния
Хэштег без публикаций — «Публикаций пока нет»; несуществующий — экран «недоступна».

## Зависимости
Используется posts, comments, stories, users; notifications.

## Критерии приёмки
- [ ] Разбор текста одинаков на backend (индекс, уведомления) и frontend (`RichText`) — общие тест-кейсы.
- [ ] Редактирование подписи обновляет связи с хэштегами; уведомление об упоминании не повторяется для того же пользователя.
- [ ] Кириллические хэштеги работают; регистр не важен.
- [ ] «Лучшие» — за 7 дней по взаимодействиям, «Недавние» — новые сначала.
