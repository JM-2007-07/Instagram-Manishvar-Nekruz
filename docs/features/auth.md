# Auth и аккаунт

## Назначение
Регистрация, вход и выход, восстановление и смена пароля. Основа для всех остальных функций.
Механика сессий — [AUTHENTICATION.md](../architecture/AUTHENTICATION.md).

## Пользовательские сценарии
1. **Регистрация:** гость заполняет `userName`, `fullName`, `email`, пароль и повтор пароля → аккаунт создан,
   пользователь вошёл (Q4) и попадает в ленту.
2. **Вход:** `userName` + пароль → лента. Неверные данные → «Неверное имя пользователя или пароль».
3. **Выход:** из меню → сессия завершена → страница входа.
4. **Забыли пароль:** email → сообщение «Если аккаунт существует, мы отправили ссылку» (всегда одинаковое).
   Ссылка `/reset-password?token=…` → новый пароль дважды → сообщение об успехе → страница входа.
5. **Смена пароля** (настройки): текущий пароль + новый дважды → успех; другие устройства разлогинены.
6. Вошедший пользователь, открывший `/login`, перенаправляется в ленту; гость на странице `(main)` — на `/login`.

## API
`POST /auth/register`, `POST /auth/login`, `POST /auth/logout`, `POST /auth/password/forgot`,
`POST /auth/password/reset`, `POST /auth/password/change`, `GET /me` (проверка сессии) —
см. [API_CONTRACT.md §2.1](../api/API_CONTRACT.md#21-auth-auth-module).

## Данные
`User`, `Session`, `PasswordResetToken` — [DATA_MODEL.md](../database/DATA_MODEL.md#аккаунт).

## Права доступа
Public: register, login, forgot, reset. Остальное — только с сессией. Все изменяющие запросы — с проверкой `Origin`.

## Валидация 📝
| Поле | Правило |
|---|---|
| `userName` | 3–30 символов, `a–z`, `0–9`, `.`, `_`; не начинается и не заканчивается точкой; хранится в нижнем регистре; уникален |
| `fullName` | 1–60 символов после обрезки пробелов |
| `email` | корректный формат, ≤ 254 символов, нижний регистр, уникален |
| пароль | 8–128 символов; не совпадает с `userName` и `email` |
| повтор пароля | только на frontend: совпадает с паролем |
| токен сброса | действителен 30 минут, одноразовый |

## Ошибки и пустые состояния
| Ситуация | Ответ API | UI |
|---|---|---|
| `userName` или `email` занят | `409 CONFLICT` (`details.field`) | ошибка у поля |
| неверные данные входа | `401 INVALID_CREDENTIALS` | общее сообщение без уточнения |
| слишком много попыток | `429` | «Слишком много попыток, повторите через N минут» |
| просроченный/использованный токен сброса | `400 BAD_REQUEST` | «Ссылка устарела» + ссылка на повторный запрос |
| неверный текущий пароль при смене | `400 BAD_REQUEST` (поле `currentPassword`) | ошибка у поля |
| сессия истекла во время работы | `401` | переход на `/login` |

## Зависимости
Фундамент Phase 0 (config, prisma, фильтр ошибок, проверка `Origin`). От auth зависят все остальные модули.

## Критерии приёмки
- [ ] Регистрация создаёт пользователя с хешем Argon2id; пароль в открытом виде нигде не сохраняется и не логируется.
- [ ] После входа браузер получает cookie `HttpOnly; SameSite=Lax`; `document.cookie` её не показывает.
- [ ] В БД хранится хеш токена сессии, а не сам токен.
- [ ] Выход удаляет сессию; повторный запрос с той же cookie → 401.
- [ ] Время ответа на вход с несуществующим `userName` сопоставимо с неверным паролем.
- [ ] `forgot` отвечает `202` одинаково для существующего и несуществующего email; ссылка появляется в логе API.
- [ ] Сброс пароля завершает все сессии; токен нельзя использовать повторно.
- [ ] Смена пароля завершает все сессии, кроме текущей.
- [ ] Изменяющий запрос с чужим `Origin` → `403 CSRF_REJECTED`.
- [ ] 6-я неудачная попытка входа за минуту → `429`.
- [ ] e2e-тесты покрывают: регистрация, вход, выход, неверный пароль, сброс пароля, смена пароля.
