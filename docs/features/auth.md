# Аккаунт и вход

> Функции F-ACC-* · API [endpoints/auth.md](../api/endpoints/auth.md) · сессии [AUTHENTICATION.md](../architecture/AUTHENTICATION.md) ·
> экраны [SCREENS.md §3.1–3.2](../design/SCREENS.md#31-вход-).

## Назначение
Регистрация с подтверждением email, вход по имени или email, вход через Facebook и Google, выход, восстановление и
смена пароля, активные сессии, смена имени пользователя и email, удаление аккаунта, двухфакторная аутентификация (P2).

## Пользовательские сценарии
1. **Регистрация (P0):** email → пароль → дата рождения → имя → имя пользователя (проверка «на лету», варианты при
   занятом) → «Зарегистрироваться» → экран «Введите код подтверждения» (6 цифр, «Отправить код ещё раз» через 60 с 📝)
   → вход и лента.
2. **Вход (P0):** «Имя пользователя, номер мобильного телефона или электронный адрес» + пароль; кнопка неактивна, пока
   поля пусты ✅; показать/скрыть пароль. Ошибка: «Неверный пароль. Проверьте его и повторите попытку.» 📝
3. **Вход через Facebook / Google (P1):** кнопка → провайдер → возврат: вход, либо экран «Выберите имя пользователя»
   с датой рождения для нового аккаунта.
4. **Выход (P0):** «Ещё» → «Выйти».
5. **Забыли пароль (P0):** имя или email → «Мы отправили ссылку…» (всегда одинаково) → ссылка → новый пароль дважды →
   вход на всех устройствах завершён → страница входа.
6. **Смена пароля (P0):** настройки → текущий и новый пароль → остальные устройства разлогинены.
7. **Активные сессии (P1):** настройки → «Где вы вошли» → устройство, браузер, время → «Выйти».
8. **Смена имени пользователя (P1), email (P1)** — в «Редактировать профиль» и настройках.
9. **Удаление аккаунта (P1):** пароль → подтверждение «Аккаунт будет удалён через 30 дней» → выход; вход в течение
   30 дней отменяет удаление.

## Данные
`User`, `Session`, `PasswordResetToken`, `EmailVerificationCode`, `OAuthAccount`, `UsernameChange` —
[DATA_MODEL.md «Аккаунт»](../database/DATA_MODEL.md#аккаунт-auth).

## Права доступа
Public: регистрация, код, вход, сброс пароля, OAuth. Остальное — с сессией. Изменяющие запросы — с проверкой `Origin`.

## Валидация 📝
| Поле | Правило |
|---|---|
| `userName` | 1–30 символов, `a–z`, `0–9`, `.`, `_`; без двух точек подряд, не начинается и не заканчивается точкой; нижний регистр; уникально; не из списка зарезервированных сегментов ([RENDERING_STRATEGY.md](../architecture/RENDERING_STRATEGY.md#2-маршруты)) |
| `fullName` | до 64 символов |
| `email` | корректный формат, ≤ 254, нижний регистр, уникален |
| `birthday` | возраст ≥ 13 лет |
| пароль | 6–128 символов 📝; не только цифры подряд вроде `123456` (список частых паролей); не совпадает с `userName` |
| код | 6 цифр, 15 минут, 5 попыток |
| смена имени пользователя | не чаще 2 раз за 14 дней; старое имя закреплено за владельцем 14 дней |

## Ошибки и пустые состояния
| Ситуация | API | UI |
|---|---|---|
| имя или email занят | `409 CONFLICT` | ошибка у поля + варианты имени |
| неверный логин/пароль | `401 INVALID_CREDENTIALS` | общее сообщение |
| email не подтверждён | `403 EMAIL_NOT_VERIFIED` | экран ввода кода с повторной отправкой |
| неверный/просроченный код | `400 VERIFICATION_CODE_INVALID` | «Код неверный. Повторите попытку» |
| слишком много попыток | `429` | «Повторите попытку через несколько минут» |
| ссылка сброса устарела | `400` | «Ссылка устарела» + повторный запрос |
| провайдер вернул ошибку | `302 /accounts/login/?error=oauth` | тост «Не удалось войти через Facebook» |
| сессия истекла | `401 UNAUTHENTICATED` | переход на `/accounts/login/` |

## Зависимости
Фундамент Phase 0, `mail`. От auth зависят все модули.

## Критерии приёмки
- [ ] Пароль хранится только как Argon2id-хеш; не логируется; не попадает в ответы.
- [ ] Регистрация без подтверждённого кода не создаёт сессию; вход до подтверждения → `403 EMAIL_NOT_VERIFIED`.
- [ ] Вход работает по имени пользователя и по email, без учёта регистра.
- [ ] После входа cookie `HttpOnly; SameSite=Lax`; `document.cookie` её не показывает; в БД — хеш токена.
- [ ] Время ответа на вход с несуществующим логином сопоставимо с неверным паролем.
- [ ] `forgot` отвечает `202` одинаково; ссылка в логе API (dev); сброс завершает все сессии; токен одноразовый.
- [ ] Смена пароля завершает все сессии, кроме текущей; завершение сессии из списка закрывает её сокеты.
- [ ] Соцвход: `state` и PKCE проверяются; новый пользователь проходит выбор имени; повторный вход находит аккаунт.
- [ ] Без ключей провайдера кнопка скрыта (`GET /auth/oauth/providers`).
- [ ] Удаление аккаунта откладывается на 30 дней и отменяется входом.
- [ ] Изменяющий запрос с чужим `Origin` → `403 CSRF_REJECTED`; 6-я неудачная попытка входа за минуту → `429`.
- [ ] e2e-тесты: регистрация с кодом, вход (имя/email), выход, неверный пароль, сброс, смена, сессии, удаление.
