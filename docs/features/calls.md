# Звонки

> Функции F-CAL-* · API [endpoints/calls.md](../api/endpoints/calls.md) · сигнализация [REALTIME.md «Звонки»](../api/REALTIME.md#звонки) ·
> [ADR 0015](../decisions/0015-webrtc-calls.md) · экран [SCREENS.md §3.12](../design/SCREENS.md#312-звонок).

## Назначение
Аудио- и видеозвонки 1:1 из Direct (P1), групповые звонки (P2), события звонков в переписке.

## Пользовательские сценарии
1. **Исходящий:** в шапке чата «Аудиозвонок» / «Видеозвонок» → запрос доступа к микрофону/камере → окно «Вызов…» со звуком.
2. **Входящий:** во всех вкладках получателя — карточка с аватаром, именем, типом, «Принять» / «Отклонить», звук.
3. **Разговор:** видео собеседника на весь экран, своё — в углу; кнопки «Микрофон», «Камера», «Завершить»; таймер;
   индикатор плохой связи 📝.
4. **Завершение:** любой участник; в чате — «Видеозвонок · 3 мин» или «Пропущенный звонок» (без ответа 30 с 📝).
5. **Групповой (P2):** из группового чата, до 4 участников сеткой.

## Данные
`Call`, `CallParticipant`, сообщение `type = CALL` — [DATA_MODEL.md «Звонки»](../database/DATA_MODEL.md#звонки-calls).

## Права доступа
Звонить можно только в чат, где я участник и нет блокировки; сигналы принимаются только от участников звонка.

## Ошибки и пустые состояния
Нет доступа к камере/микрофону — пояснение, как разрешить; собеседник занят — «Пользователь сейчас на другом звонке»
(`409`); нет соединения (NAT без TURN) — «Не удалось подключиться» через 20 с 📝.

## Зависимости
chats, realtime, privacy; TURN — Q34.

## Критерии приёмки
- [ ] Звонок между двумя браузерами на одной машине и в одной сети: звук и видео в обе стороны.
- [ ] Входящий показывается во всех вкладках; принятие в одной закрывает окно в остальных.
- [ ] Пропущенный и завершённый звонки создают сообщения-события с длительностью.
- [ ] Сигналы от не-участника отклоняются; блокировка запрещает звонок.
- [ ] Выключение микрофона/камеры видно собеседнику (значок).
