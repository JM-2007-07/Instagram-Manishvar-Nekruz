# Подписки

## Назначение
Подписка на пользователей; списки подписчиков и подписок. Основа ленты постов и ленты сторис.

## Пользовательские сценарии
1. На чужом профиле — «Подписаться» → кнопка меняется на «Вы подписаны», счётчик подписчиков +1.
2. «Вы подписаны» → «Отписаться» → счётчик −1.
3. Клик по счётчику «подписчики» / «подписки» → список пользователей с кнопками подписки.

## API
`PUT /users/{userId}/follow`, `DELETE /users/{userId}/follow`, `GET /users/{userId}/followers`,
`GET /users/{userId}/following` — [API_CONTRACT.md §2.3](../api/API_CONTRACT.md#23-follows-follows-module).

## Данные
`Follow(followerId, followingId, createdAt)`; составной первичный ключ; CHECK `followerId <> followingId`.

## Права доступа
Любой вошедший видит списки любого пользователя (Q22); подписка — от своего имени (из сессии).

## Валидация
- `userId` — UUID существующего пользователя (иначе `404`).
- Подписка на себя → `400 BAD_REQUEST`.
- Повторная подписка / отписка без подписки — успешны (`204`), состояние не меняется.

## Ошибки и пустые состояния
- «Нет подписчиков» / «Нет подписок».
- Ошибка сети при подписке → кнопка возвращается в исходное состояние, toast.

## Зависимости
auth, users (профиль). От follows зависят: лента (`/feed`), лента сторис, счётчики профиля.

## Критерии приёмки
- [ ] `PUT` дважды подряд создаёт одну запись; `DELETE` дважды — без ошибки.
- [ ] Подписка на себя → `400`; на несуществующего → `404`.
- [ ] Списки пагинированы, новые подписки сначала, содержат `UserSummary`.
- [ ] После подписки профиль и лента обновляются без перезагрузки страницы.
