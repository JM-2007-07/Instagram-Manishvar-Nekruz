# История поиска

## Назначение
Две личные истории из исходного Swagger: **текстовые запросы** (#42–#45) и **пользователи, открытые из поиска** (#46–#49).

## Пользовательские сценарии
1. Открыть поиск с пустым полем → «Недавнее»: пользователи и запросы, новые сначала.
2. Отправить запрос (Enter) → текст сохраняется в историю запросов.
3. Открыть профиль из результатов поиска → пользователь сохраняется в историю пользователей.
4. Крестик у записи → удалить одну; «Очистить всё» → удалить все записи этого типа.
5. Клик по запросу из истории → повторный поиск; по пользователю → профиль.

## API
`GET|POST|DELETE /me/search-history/queries[/{entryId}]`, `GET|POST|DELETE /me/search-history/users[/{entryId}]` —
[API_CONTRACT.md §2.7](../api/API_CONTRACT.md#27-search-history-search-history-module).

## Данные
`TextSearchEntry(userId, text)` и `UserSearchEntry(userId, searchedUserId)` — уникальные пары; повтор обновляет `createdAt`.

## Права доступа
Только владелец: чтение, добавление, удаление. Чужая запись → `404`.

## Валидация 📝
- `text`: 1–100 символов после обрезки.
- `userId`: существующий пользователь, не сам пользователь.
- Хранится не более 50 последних записей каждого типа (старые удаляются при добавлении).

## Ошибки и пустые состояния
- История пуста → «Нет недавних запросов».
- Удалённый пользователь из истории исчезает (каскадное удаление).

## Зависимости
auth, users (поиск пользователей).

## Критерии приёмки
- [ ] Повторный поиск того же текста не создаёт дубликат, а поднимает запись наверх.
- [ ] Пользователь не видит и не может удалить чужие записи.
- [ ] «Очистить всё» удаляет только записи своего типа.
- [ ] Лимит 50 записей соблюдается.

## Открытые вопросы
Нет специфичных; общий Q1 (обязательность функции).
