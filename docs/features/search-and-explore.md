# Поиск, «Интересное», история поиска

> Функции F-SRC-* · API [endpoints/search.md](../api/endpoints/search.md), «Интересное» — [posts.md](../api/endpoints/posts.md) ·
> экран [SCREENS.md §3.8](../design/SCREENS.md#38-интересное-) · размеры [DESIGN_SYSTEM.md §4.4](../design/DESIGN_SYSTEM.md#44-интересное-).
> Исходный Swagger: #41 (поиск пользователей), #42–#49 (история поиска).

## Назначение
Страница «Интересное» с поиском, поиск аккаунтов, хэштегов и мест, недавние запросы.

## Пользовательские сценарии
1. **«Интересное» (P0):** `/explore/` — строка поиска ✅, сетка 3 колонки 3:4 ✅ с постами и reels, бесконечная прокрутка.
2. **Поиск (P0):** ввод → через ~300 мс список: аккаунты (аватар, имя пользователя, галочка, имя, «Подписаны»),
   хэштеги («#tag · N публикаций»), места.
3. **Недавнее (P0):** фокус в пустом поле → «Недавнее» с «Очистить все»; у записи — «✕».
4. Клик по результату → профиль / хэштег / место; запись в историю поиска (того же типа). Enter — запрос в историю (`QUERY`).

## Данные
`SearchHistoryEntry` (типы `QUERY`, `USER`, `HASHTAG`, `LOCATION`) — [DATA_MODEL.md «Поиск»](../database/DATA_MODEL.md#поиск-search).

## Права доступа
История — только владелец. Результаты не включают заблокированных в обе стороны; закрытые аккаунты находятся
(шапка видна), их контент — нет.

## Валидация 📝
`q` 1–50 символов; история — до 50 записей каждого типа, повтор поднимает запись наверх.

## Ошибки и пустые состояния
«Ничего не найдено»; «Нет недавних запросов».

## Зависимости
users, tags, locations, posts (`/explore`), privacy.

## Критерии приёмки
- [ ] Поиск находит по началу и вхождению `userName` и `fullName`, без учёта регистра; не находит по email.
- [ ] Подписки и популярные аккаунты выше в результатах.
- [ ] Повторный поиск не создаёт дубликат, а поднимает запись; «Очистить все» удаляет только записи пользователя.
- [ ] «Интересное» не показывает посты закрытых аккаунтов, заблокированных и уже свои.
- [ ] Сетка совпадает с DESIGN_SYSTEM §4.4.
