## Роли

| Термин | Значение |
|---|---|
| **Студент A / Студент B** | два разработчика; кто есть кто — Q26. A владеет фундаментом backend и модулями auth, users, follows, search-history, locations, chats; B — фундаментом frontend и модулями storage/media, posts, stories |
| **Владелец модуля** | отвечает за backend, frontend и спецификацию модуля; изменения в чужом модуле — по договорённости |
| **Агент** | ИИ-ассистент, работающий в репозитории по [AGENTS.md](../AGENTS.md) |

## Уровни доступа (колонка «Доступ» в API_CONTRACT)

| Термин | Значение |
|---|---|
| **Public** | без сессии |
| **User** | любой вошедший пользователь |
| **Owner** | только владелец ресурса (автор поста, сторис, записи истории) |
| **Member** | только участник чата |
| **Admin** | пользователь с ролью `ADMIN` (Q6) |

## Предметная область

| Термин | Значение |
|---|---|
| **Пост** | публикация: 1–10 изображений или одно видео + необязательные `title`, `content` |
| **Reel** | пост с одним видео (`isReel = true`), Q10 |
| **Лента (feed)** | посты тех, на кого я подписан, и мои, новые сначала — `GET /feed` |
| **«Интересное» (explore)** | все посты, новые сначала — `GET /posts` |
| **Сторис (story)** | временная публикация на 24 часа (Q11): изображение/видео или ссылка на свой пост |
| **Подписка (follow)** | `follower` подписан на `following`; подписчики = followers, подписки = following |
| **Избранное (favorites, «Сохранённое»)** | личный список сохранённых постов |
| **Просмотр (view)** | отметка «пользователь видел пост/сторис», одна на пользователя (Q14) |
| **Чат** | личная переписка ровно двух пользователей |
| **История поиска** | два списка: текстовые запросы и пользователи, открытые из поиска |
| **Локация** | запись справочника: город, регион, индекс, страна (назначение — Q20) |

## Технические термины

| Термин | Значение в проекте |
|---|---|
| **Сессия** | запись `Session` в PostgreSQL; браузер хранит только случайный токен в HttpOnly cookie |
| **HttpOnly cookie** | cookie, недоступная JavaScript; защищает токен от кражи через XSS |
| **CSRF** | подделка запроса с чужого сайта; защита — `SameSite=Lax` + проверка `Origin` |
| **Same-origin прокси** | правило `rewrites` в Next.js: браузер обращается к `/api/v1/...` на адресе сайта, Next.js пересылает в NestJS |
| **Контракт** | описание API: `API_CONTRACT.md` → после Phase 0 — Swagger NestJS (`docs/api/openapi.json`) |
| **`npm run contract`** | экспорт Swagger из NestJS + генерация типов frontend (`schema.d.ts`) |
| **DTO** | класс NestJS, описывающий и проверяющий тело/параметры запроса или ответ |
| **Guard** | класс NestJS, решающий, пропускать ли запрос (у нас — `SessionGuard`) |
| **Server / Client Component** | компонент Next.js, выполняемый на сервере / в браузере (`'use client'`) |
| **Инвалидация** | пометка кэша TanStack Query устаревшим, чтобы данные загрузились заново |
| **Миграция** | SQL-файл Prisma, переводящий БД из одной версии схемы в другую |
| **Seed** | скрипт с тестовыми данными для локальной БД |
| **ADR** | короткая запись архитектурного решения: контекст, решение, альтернативы, последствия |
| **Harness** | всё, что помогает агенту работать надёжно: AGENTS.md, карта документов, STATUS, сценарии, проверки в CI |
| **Polling** | периодический повторный запрос (вместо real-time) |
