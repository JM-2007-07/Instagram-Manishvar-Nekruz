# Стратегия тестирования

> Статус: 📝 предложено. Инструменты устанавливаются в Phase 0; тесты пишутся вместе с функциями.

## Принцип

Тестируем то, что легко сломать и важно для пользователя: **правила доступа, бизнес-правила и
ключевые сценарии API**. Не тестируем сам фреймворк, геттеры и разметку без логики.

## Уровни

| Уровень | Инструмент | Что проверяем | Где |
|---|---|---|---|
| Юнит (backend) | Jest (стандарт NestJS) | сервисы: правила владения, валидация бизнес-правил, расчёт сроков (сторис, сессии) — с подменой Prisma | `apps/api/src/**/*.spec.ts` |
| e2e API | Jest + supertest, реальная БД `instagram_test` | полный путь запроса: guard → DTO → сервис → БД → формат ответа/ошибки | `apps/api/test/*.e2e-spec.ts` |
| Юнит/компоненты (frontend) | Vitest + React Testing Library | компоненты с логикой: формы, оптимистичные обновления, разбор ошибок API | `apps/web/src/**/*.test.tsx` |
| Реальное время | Jest + `socket.io-client` против запущенного приложения в e2e | доставка событий участникам, отказ чужим и без сессии | `apps/api/test/*.realtime.e2e-spec.ts` |
| Сквозные сценарии | Playwright (T7.1), два контекста браузера для Direct и звонков | регистрация → пост → лайк → комментарий; Direct; история | `apps/web/e2e/` |
| Звонки | ручная проверка: два профиля браузера на одной машине | звук и видео в обе стороны | чек-лист в calls.md |
| Контракт | `npm run contract` + `typecheck` в CI | frontend соответствует Swagger backend | CI |

## Минимум для каждого endpoint'а (e2e)
1. Успешный сценарий: статус и форма ответа.
2. Без сессии → `401` (для не-публичных).
3. Чужой ресурс → `403`/`404` по правилам [SECURITY.md](../architecture/SECURITY.md#авторизация).
4. Невалидный ввод → `400 VALIDATION_ERROR`.
5. **Приватность** (для выдач): заблокированный и неподписанный на закрытый аккаунт объект не получают (REST, `GET /media/{id}`, событие).

## Тестовые данные
- e2e-тесты очищают БД перед каждым файлом тестов (truncate) и создают данные через фабрики-функции.
- Файлы при e2e пишутся во временный каталог (`STORAGE_LOCAL_DIR`), очищаемый после тестов.
- Не используются реальные email и пароли.

## CI
`npm run lint` → `npm run typecheck` → `npm run test` (юнит) → e2e API с PostgreSQL как service container
GitHub Actions → проверка контракта. PR не вливается при красном CI.

## Покрытие
Целевого процента нет. Вместо этого — правило: у каждого правила доступа и бизнес-правила из
спецификации функции есть хотя бы один тест.
