# Чек-лист качества

Используется автором PR перед запросом ревью и ревьюером. Не каждый пункт применим к каждому PR.

## Общее
- [ ] Изменения соответствуют задаче из [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md) и модулю автора.
- [ ] Общие файлы (см. [CONTRIBUTING.md](../CONTRIBUTING.md#общие-файлы)) изменены только по договорённости.
- [ ] Код понятен без автора: ясные имена, нет мёртвого кода, нет закомментированных блоков.
- [ ] Нет новых зависимостей без обоснования в описании PR.
- [ ] Нет преждевременных абстракций (generic-обёрток, «универсальных» сервисов, лишних слоёв).
- [ ] Комментарии объясняют неочевидные решения, а не пересказывают код.

## Backend
- [ ] Каждый входной параметр описан в DTO с валидацией; id в пути — `ParseUUIDPipe`.
- [ ] Текущий пользователь берётся из `@CurrentUser()`, не из тела/query.
- [ ] Проверка прав выполняется до изменения данных; чужие приватные ресурсы → 404.
- [ ] Выдача проходит `VisibilityService`: блокировки в обе стороны, закрытые аккаунты, аудитория историй, ограниченные.
- [ ] Уведомления и события Socket.IO отправляются после успешной транзакции и только тем, кто вправе видеть объект.
- [ ] Ответ содержит только явно выбранные поля (нет `passwordHash`, чужих email).
- [ ] Ошибки — через стандартные исключения NestJS → единый формат; коды соответствуют контракту.
- [ ] Многотабличные изменения — в транзакции.
- [ ] Списки — курсорные (`{ items, nextCursor }`), `limit` ≤ 50.
- [ ] Для чувствительных операций настроен rate limit.
- [ ] Swagger-описание endpoint'а полное (ответы, коды ошибок).

## Frontend
- [ ] Запросы только через RTK Query: эндпоинты в `features/<name>/api.ts` (`injectEndpoints`); нет `fetch`/`useEffect` для загрузки данных в компонентах.
- [ ] Используются сгенерированные типы; нет ручных копий типов API.
- [ ] Есть состояния: загрузка, пусто, ошибка.
- [ ] У каждого запроса есть `providesTags`, у каждой мутации — `invalidatesTags` по таблице API_REQUEST_ARCHITECTURE.md §6.3; оптимистичные обновления — только случаи §6.5 (лайки, сохранение, сообщения, реакции).
- [ ] `page.tsx` — Server Component без загрузки данных; данные — хуки RTK Query в Client Component функции.
- [ ] Нет `dangerouslySetInnerHTML`; пользовательский текст выводится как текст.
- [ ] Работает на мобильной ширине; у полей есть подписи; доступно с клавиатуры.
- [ ] Дизайн: только токены DESIGN_SYSTEM, размеры §4, раскладка по SCREENS.md; проверено в светлой и тёмной теме на 375 и 1150 px.
- [ ] Нет логотипа, названия, шрифта и иконок Instagram (ADR 0012).

## Контракт и база данных
- [ ] При изменении API: обновлены `API_CONTRACT.md`, `openapi.json`, `schema.d.ts` (`npm run contract`).
- [ ] При изменении схемы: одна миграция, создана после rebase на `main`, SQL просмотрен; CHECK-ограничения добавлены вручную, если нужны.
- [ ] Влитые миграции не изменены.

## Безопасность
- [ ] Нет секретов, паролей, токенов в коде, логах и тестовых снимках.
- [ ] Загрузки: лимит размера, проверка типа по содержимому, случайное имя файла.
- [ ] Новые изменяющие endpoint'ы не используют `GET`.

## Тесты
- [ ] Юнит-тесты для новых бизнес-правил и правил доступа (включая «чужой пользователь не может…»).
- [ ] e2e-тест для нового endpoint'а с основным и хотя бы одним ошибочным сценарием.
- [ ] Тесты не дублируют друг друга и не проверяют сам фреймворк.
- [ ] `npm run lint`, `npm run typecheck`, `npm run test` проходят.

## Документация
- [ ] Спецификация функции обновлена, если поведение изменилось; закрытые вопросы Q отмечены в REQUIREMENTS.md.
- [ ] Новые архитектурные решения оформлены как ADR.
- [ ] Создана история в `docs/stories/`; STATUS.md: статус задачи, ветка/PR и строка в оглавлении историй обновлены.
