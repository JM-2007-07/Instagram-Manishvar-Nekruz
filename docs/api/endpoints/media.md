# Эндпоинты: `media`

> Модуль `media` · сквозной механизм загрузки и раздачи файлов · ADR [0007](../../decisions/0007-media-storage.md), [0016](../../decisions/0016-media-processing.md) ·
> лимиты — [SECURITY.md](../../architecture/SECURITY.md#загрузка-файлов).

| Метод и путь | Доступ | Запрос | Ответ | Ошибки |
|---|---|---|---|---|
| `POST /media` | User | `multipart/form-data`: `file`, `purpose` (`POST` / `REEL` / `STORY` / `AVATAR` / `MESSAGE` / `VOICE` / `HIGHLIGHT_COVER`) | `201 MediaItem` (`status: PROCESSING` для видео/аудио, `READY` для изображений после обработки) | 413, 415, 429 |
| `GET /media/{mediaId}/status` | Owner | — | `MediaItem` | 404 |
| `GET /media/{mediaId}` | User + видимость объекта, к которому привязан файл | `?variant=thumb` | файл (`Content-Type`, `Cache-Control: private`, поддержка `Range` для видео) | 404 |
| `DELETE /media/{mediaId}` | Owner | — | `204` — только не привязанный файл | 409 |

Правила:
- Двухшаговый сценарий: загрузить файлы (с прогрессом по каждому) → передать их `id` в создание поста, истории,
  сообщения, аватара. Файл можно привязать один раз и только к объекту своего владельца.
- Не привязанные за 24 часа 📝 файлы удаляет фоновая задача.
- Доступ к файлу = доступ к объекту: пост закрытого аккаунта — подписчикам; вложение чата — участникам; история — по
  аудитории и «скрыть от»; аватар — всем вошедшим (кроме блокировки).
- Сквозная проверка типа по содержимому, удаление EXIF, превью, перекодирование — ADR 0016.
