# События реального времени (Socket.IO)

> Статус: 📝 проект ([ADR 0013](../decisions/0013-realtime-socketio.md)). Модуль backend — `realtime` (шлюз) + модули-источники.
> Модели (`Message`, `Notification`, `Call`…) — [API_CONTRACT.md §1.4](API_CONTRACT.md#14-модели-ответов-).

## Подключение

| Тема | Правило |
|---|---|
| Адрес | `NEXT_PUBLIC_REALTIME_URL` (dev `http://localhost:4000`), путь `/socket.io/` |
| Аутентификация | cookie сессии при рукопожатии; `Origin` = `WEB_ORIGIN`; иначе отключение с `connect_error: UNAUTHENTICATED` |
| Комнаты | сервер помещает сокет в `user:{userId}`; события чата рассылаются в комнаты всех участников |
| Несколько вкладок | все вкладки пользователя в одной комнате; событие получает каждая |
| Переподключение | автоматическое (клиент Socket.IO); после переподключения клиент сбрасывает теги RTK Query `Chat`, `Message`, `Notification` и запрашивает `GET /me/badges`, чтобы не потерять пропущенное |
| Источник истины | REST; события только сообщают об изменении. Клиент, отправивший изменение, получает событие тоже (для других вкладок) |

## Сервер → клиент

| Событие | Данные | Когда | Реакция frontend |
|---|---|---|---|
| `message:new` | `{ message: Message }` | новое сообщение в чате пользователя | добавить в начало кэша `getMessages(chatId)`; обновить `getChats`; звук/значок, если чат не открыт |
| `message:updated` | `{ message }` | редактирование | заменить в кэше |
| `message:unsent` | `{ chatId, messageId }` | отмена отправки | убрать из кэша |
| `message:reaction` | `{ chatId, messageId, reactions }` | реакция поставлена/снята | обновить сообщение |
| `chat:updated` | `{ chat: Chat }` | название, фото, участники, принятие запроса | заменить в кэше |
| `chat:read` | `{ chatId, userId, messageId }` | участник прочитал | «Просмотрено» / аватары прочитавших |
| `chat:typing` | `{ chatId, userId, isTyping }` | участник печатает (гаснет сам через 5 с 📝) | индикатор «печатает…» |
| `presence:updated` | `{ userId, isOnline, lastActiveAt }` | собеседник появился/ушёл (с учётом `showActivityStatus` обоих) | «В сети» / «Был(а) N мин назад» |
| `notification:new` | `{ notification: Notification }` | новое уведомление | добавить в кэш, точка на «Уведомления» |
| `badges:updated` | `{ unreadNotifications, unreadChats, followRequests }` | изменились счётчики | обновить значки меню |
| `media:processed` | `{ mediaId, status }` | обработка файла завершена | обновить превью при создании публикации/сообщения |
| `post:published` | `{ postId }` | публикация с видео готова | тост «Публикация опубликована», сбросить `Feed` |

### Звонки

| Событие | Данные | Когда |
|---|---|---|
| `call:incoming` | `{ call: Call }` | входящий звонок — окно «Принять / Отклонить» во всех вкладках |
| `call:accepted` | `{ callId, userId }` | собеседник принял — начать обмен SDP |
| `call:declined` | `{ callId, userId }` | отклонил |
| `call:ended` | `{ call }` | звонок завершён/пропущен — закрыть окно |
| `call:signal` | `{ callId, fromUserId, kind: "offer" \| "answer" \| "ice", payload }` | сигнал WebRTC от собеседника |

## Клиент → сервер

| Событие | Данные | Проверка на сервере |
|---|---|---|
| `chat:typing` | `{ chatId, isTyping }` | отправитель — участник чата; не чаще раза в 2 с 📝 |
| `call:signal` | `{ callId, toUserId, kind, payload }` | оба — участники звонка; звонок `RINGING`/`ONGOING`; размер `payload` ≤ 64 КБ 📝 |

Подтверждения (`ack`) возвращают `{ ok: true }` или `{ ok: false, code }` с кодами из API_CONTRACT §1.2.

## Безопасность

- Событие получают только пользователи, которые имеют право видеть объект (те же правила, что у REST).
- Блокировка прекращает доставку событий между пользователями (сообщения, присутствие, печатает).
- Данные событий не содержат email, токенов и полей, которых нет в REST-ответах.
