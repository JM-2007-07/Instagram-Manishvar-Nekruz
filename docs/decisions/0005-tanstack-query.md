# 0005. TanStack Query + openapi-fetch

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Нужен один понятный способ запросов с клиента: кэш, состояния загрузки и ошибок, бесконечные ленты,
обновление после изменений, типизация по контракту.

## Решение

- **openapi-fetch** — единственный HTTP-клиент (браузер и Server Components), типизирован сгенерированными типами.
- **TanStack Query** — состояние серверных данных в Client Components.
- Server Actions и глобальный store (Redux/Zustand) не используются.

## Рассмотренные альтернативы

- **RTK Query** — требует Redux store, который больше ни для чего не нужен.
- **fetch + useEffect** — много однотипного кода и ошибок (гонки, ручная инвалидация).
- **SWR** — проще, но слабее в мутациях и бесконечных списках; разница в сложности небольшая.
- **Своя обёртка над fetch** — пришлось бы вручную типизировать каждый endpoint.

## Последствия

- Запросы и ключи кэша живут в `features/<name>/api.ts`; компоненты используют хуки.
- Правила инвалидации — в [API_REQUEST_ARCHITECTURE.md §6.3](../architecture/API_REQUEST_ARCHITECTURE.md#63-правила-инвалидации).
