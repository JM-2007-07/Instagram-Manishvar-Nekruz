# Архитектурные решения (ADR)

ADR (Architecture Decision Record) — короткая запись: какое решение принято, почему и какие альтернативы
рассматривались. Нужна, чтобы через месяц (и на защите) объяснить, **почему** код устроен так.

## Как добавить ADR

1. Новый файл `NNNN-короткое-название.md` по шаблону ниже, статус «Предложено».
2. PR; второй разработчик одобряет → статус «Принято».
3. Решение не переписывается задним числом: если оно меняется — новый ADR со ссылкой
   «заменяет NNNN», а у старого статус «Заменено».

```markdown
# NNNN. Название
- Статус: Предложено | Принято | Заменено (NNNN)
- Дата: YYYY-MM-DD
## Контекст
## Решение
## Рассмотренные альтернативы
## Последствия
```
