# 0020. Развёртывание на Render: один публичный адрес через API

- Статус: Принято
- Дата: 2026-10-24
- Дополняет: [0004](0004-same-origin-proxy.md), [0013](0013-realtime-socketio.md); закрывает Q24 для показа на экзамене

## Контекст

Студент A выбрал Render, бесплатный план. Сессия — HttpOnly cookie, а Socket.IO проверяет ту же cookie (ADR 0013),
поэтому страницы, REST и `/socket.io/` должны быть на **одном** origin. На Render каждый сервис получает свой адрес
`*.onrender.com` — это разные сайты, cookie одного не уходит в другой. Свой домен не покупаем. Бесплатные сервисы
Render не принимают трафик по внутренней сети — только по публичному адресу.

## Решение

1. Два бесплатных web-сервиса и бесплатная PostgreSQL (`render.yaml` в корне):
   `instagram-api` (NestJS) и `instagram-web` (Next.js).
2. **Публичный адрес — `instagram-api`.** Он сам отвечает на `/api/v1/*` и `/socket.io/*`, а все остальные пути
   пересылает в `instagram-web` (`http-proxy-middleware`, `src/web-proxy.ts`, переменная `WEB_UPSTREAM_URL`).
   Без переменной (разработка, тесты) ничего не пересылается.
3. `WEB_ORIGIN` API = его же публичный адрес; у Next.js `API_INTERNAL_URL`, `NEXT_PUBLIC_REALTIME_URL` и
   `PUBLIC_ORIGIN` — тот же адрес. `proxy.ts` строит редирект на вход от `PUBLIC_ORIGIN`.
4. `TRUST_PROXY=true`: перед API стоит балансировщик Render, иначе все клиенты выглядели бы одним IP для rate limit.
5. Миграции — `prisma migrate deploy` при каждом запуске API (на бесплатном плане нет pre-deploy).

## Рассмотренные альтернативы

- **Свой домен** (`example.com` + `api.example.com`, cookie на домен) — нужен купленный домен и DNS.
- **Один сервис с обоими приложениями** — одна машина 512 МБ на Next.js, NestJS и ffmpeg; риск нехватки памяти.
- **Токен для Socket.IO в JavaScript** — противоречит правилу «JS не читает токен» и требует изменения API.

## Последствия

- Каждая страница проходит через два сервиса — немного медленнее; оба «засыпают» через 15 минут без запросов,
  первый вход после сна — около минуты.
- **Диск бесплатного сервиса временный:** загруженные фото, видео и голосовые пропадают при перезапуске, новом
  деплое и после сна. Для постоянного хранения нужен платный план с диском или драйвер `s3` (T5.B2).
- Бесплатная база удаляется через 30 дней (+14 дней на переход на платный план).
- Проверено локально (порты 4200 → 3200): редирект гостя, вход, REST, Socket.IO и доставка сообщения через один адрес.
