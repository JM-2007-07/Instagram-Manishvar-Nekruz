# 0015. Аудио- и видеозвонки: WebRTC

- Статус: Принято (TURN для продакшена — Q34)
- Дата: 2026-10-21

## Контекст

Звонки 1:1 из Direct (F-CAL-01…03), позже — групповые (F-CAL-04).

## Решение

1. **WebRTC peer-to-peer** в браузере: медиа идёт напрямую между участниками, сервер не обрабатывает звук и видео.
2. **Сигнализация** — через Socket.IO (ADR 0013): `call:invite`, `call:accept`, `call:decline`, `call:offer`, `call:answer`,
   `call:ice-candidate`, `call:end` ([REALTIME.md](../api/REALTIME.md)).
3. **Запись о звонке** — REST и таблица `Call` (кто, кому, тип, статус, длительность); в чат добавляется сообщение-событие
   («Пропущенный звонок», «Видеозвонок, 3 мин»).
4. **STUN/TURN:** в разработке — публичный STUN (`stun:stun.l.google.com:19302`); для звонков через строгие NAT в
   продакшене нужен TURN (свой coturn или сервис) — Q34. Настройки ICE отдаются backend'ом (`GET /calls/ice-servers`),
   учётные данные TURN — временные.
5. **Групповые звонки (P2)** — сетка peer-to-peer до 4 участников; больше — медиасервер (SFU), отдельный ADR.

## Рассмотренные альтернативы

- **Готовые сервисы (Twilio, LiveKit Cloud)** — платные и требуют аккаунта.
- **Медиасервер сразу** — сложно и не нужно для звонков 1:1.

## Последствия

- Браузер запрашивает доступ к микрофону и камере; HTTPS обязателен в продакшене (localhost разрешён).
- Тестирование: два браузера / два профиля на одной машине.
