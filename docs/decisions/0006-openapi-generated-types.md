# 0006. Типы frontend генерируются из Swagger NestJS

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Типы запросов/ответов нужны обоим приложениям. Ручное дублирование типов расходится с реальным API;
общий пакет типов становится «свалкой» и требует дисциплины синхронизации.

## Решение

- Источник истины — DTO NestJS с декораторами Swagger.
- `npm run contract`: backend экспортирует `docs/api/openapi.json`; `openapi-typescript` генерирует
  `apps/web/src/lib/api/schema.d.ts`. Оба файла коммитятся.
- CI повторяет генерацию и падает при расхождении; `typecheck` ловит вызовы несуществующих endpoint'ов.

## Рассмотренные альтернативы

- **`packages/shared-types`** — ручная синхронизация, риск циклических зависимостей.
- **Генераторы клиентов с хуками (orval и т.п.)** — генерируют много кода, который сложно объяснить.

## Последствия

- Изменение API без обновления контракта не пройдёт CI.
- DTO backend должны быть полностью описаны для Swagger (CLI-плагин `@nestjs/swagger` берёт большую часть из типов).

## Дополнение (2026-10-21)

После [ADR 0010](0010-rtk-query.md) (RTK Query вместо openapi-fetch) генерация типов сохраняется, но `typecheck`
проверяет только **формы данных** (поля ответов и тел через псевдонимы в `lib/api/types.ts`), а не URL эндпоинтов.
Пути сверяются с API_CONTRACT.md агентом `reviewer` и проверяются e2e-сценариями Playwright (T5.2).
