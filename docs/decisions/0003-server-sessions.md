# 0003. Серверные сессии и HttpOnly cookie

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Исходный API использует Bearer JWT, который пришлось бы хранить в JavaScript (уязвимо при XSS).
Требование проекта — серверные сессии и HttpOnly cookie.

## Решение

- Сессии в таблице `Session` PostgreSQL; браузер хранит случайный токен в cookie
  `HttpOnly; SameSite=Lax; Secure` (в продакшене `__Host-sid`); в БД — SHA-256 хеш токена.
- Пароли — Argon2id.
- CSRF: `SameSite=Lax` + проверка `Origin` для изменяющих запросов.

Подробно: [AUTHENTICATION.md](../architecture/AUTHENTICATION.md), [SECURITY.md](../architecture/SECURITY.md#csrf).

## Рассмотренные альтернативы

- **JWT в HttpOnly cookie** — нельзя мгновенно отозвать без списка отзыва (а это та же таблица сессий);
  больше понятий для объяснения.
- **Сессии в Redis** — быстрее, но Redis пока не нужен ни для чего другого. Перенос возможен позже без изменения API.
- **Библиотеки (Passport, express-session)** — скрывают простую логику за абстракциями; собственный guard
  на ~100 строк понятнее для защиты проекта.

## Последствия

- Один запрос к БД на проверку сессии (индекс по `tokenHash`); для учебной нагрузки несущественно.
- Выход, смена пароля и удаление аккаунта мгновенно завершают сессии.
