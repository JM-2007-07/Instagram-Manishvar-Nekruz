# 0002. Новый REST API `/api/v1`

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Исходный Swagger (ASP.NET, 57 операций) — ориентир по функциональности, но содержит проблемы:
пароли в URL, неверные HTTP-методы, JWT в JavaScript, несогласованные имена, нет схем ответов
(см. [API_INVENTORY.md](../api/API_INVENTORY.md#выявленные-проблемы-и-пробелы)). Мы пишем и frontend, и backend сами;
внешних клиентов старого API нет.

## Решение

Спроектировать единообразный REST API под `/api/v1`, **покрывающий все 57 исходных операций**,
с таблицей соответствия в [API_CONTRACT.md](../api/API_CONTRACT.md#3-таблица-соответствия-исходная-операция--новый-endpoint).

## Рассмотренные альтернативы

- **Повторить исходные пути один в один** — сохранило бы небезопасные и неудобные решения.
- **Сохранить пути, исправить только безопасность** — половинчато: остались бы `get-…`/`add-…`, id в query и разнобой регистра.

## Последствия

- Преподавателю можно показать соответствие каждой исходной операции новому endpoint.
- Неизвестные в исходнике формы ответов определяем сами (черновики в контракте → DTO NestJS).
- Версия `v1` позволяет в будущем менять контракт без поломки старых клиентов (сейчас не требуется).
