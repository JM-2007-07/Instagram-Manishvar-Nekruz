# 0007. Хранилище медиа: локально → S3-совместимое

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Изображения и видео не хранятся в PostgreSQL. Облачные хранилища (Cloudflare R2, Amazon S3) требуют
аккаунта; на этапе разработки платные сервисы и продакшен-ключи не используются. Docker (для MinIO) не установлен.

## Решение

- `StorageService` с небольшим интерфейсом: `save(key, stream, mimeType)`, `delete(key)`, `read(key)`.
- Драйвер **`local`** (каталог `apps/api/storage/`, в `.gitignore`) — реализуется в Phase 1.
- Драйвер **`s3`** (`@aws-sdk/client-s3`; R2 и S3 совместимы) — реализуется при подготовке к деплою; выбор R2/S3 — Q25.
- Метаданные — в таблице `MediaFile`; файлы отдаются через `GET /api/v1/media/{id}` с проверкой прав.

## Рассмотренные альтернативы

- **Сразу R2/S3** — требует аккаунта и ключей у обоих разработчиков.
- **MinIO в Docker** — хороший способ проверить драйвер `s3` локально; добавим вместе с Docker.
- **Файлы в БД (bytea)** — раздувает БД и бэкапы; противоречит требованиям.

## Последствия

- Это единственная абстракция «на будущее» в проекте — оправдана тем, что смена хранилища запланирована.
- Переход на S3 не меняет API: `GET /media/{id}` может начать отвечать редиректом на подписанную ссылку.
