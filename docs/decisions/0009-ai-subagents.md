# 0009. ИИ-агенты с разделением по моделям

- Статус: Принято
- Дата: 2026-10-21

## Контекст

Проект ведут два студента с помощью Claude Code. Один агент на всё либо тратит дорогую модель на рутину,
либо пишет код без тщательного плана и ревью. Нужно разделить работу так, чтобы рассуждение, написание кода
и механические проверки выполнялись подходящими моделями, а результат оставался проверяемым.

## Решение

Восемь агентов в `.claude/agents/` с конвейером, описанным в [AI_AGENTS.md](../development/AI_AGENTS.md):

- **Opus** (план, контракт/схема, ревью): `planner`, `contract-designer`, `reviewer`.
- **Sonnet** (код и тесты): `backend-dev`, `frontend-dev`, `test-writer`.
- **Haiku** (рутина): `verifier`, `docs-keeper`.

Основная сессия — оркестратор: общается с пользователем, передаёт результаты между агентами, делает коммиты.
Агенты не коммитят, не вызывают друг друга и ограничены своими файлами.

## Рассмотренные альтернативы

- **Один агент на всё** — проще, но без отдельного планирования и независимого ревью; рутина на дорогой модели.
- **Агент на каждый модуль** — дублирование инструкций; границы модулей проще передавать в задании.
- **Всё на Opus** — максимальное качество, но высокая стоимость и скорость ниже без выигрыша на механических задачах.

## Последствия

- Каждая задача проходит план → реализацию → проверку → ревью → обновление STATUS.md.
- Определения агентов — общие файлы; их правила должны совпадать с AGENTS.md (при изменении AGENTS.md — проверить агентов).
- Агенты Claude Code-специфичны; другие ИИ используют те же роли как сценарии из AI_AGENTS.md.
