# 0001. Монорепозиторий на pnpm workspaces

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Frontend и backend должны жить в одном репозитории, оставаясь отдельными приложениями.
Над проектом работают два студента; инструменты должны быть понятными.

## Решение

- pnpm workspaces (`pnpm-workspace.yaml`: `apps/*`), pnpm 12.8.2 через corepack, Node.js 24.
- Без Turborepo/Nx: корневые скрипты с `pnpm --filter`.
- Каталог `packages/` не создаётся, пока нет кода, реально нужного обоим приложениям.

## Рассмотренные альтернативы

- **npm workspaces** — не требуют установки, но не запрещают импорт пакетов, не объявленных в
  `package.json` приложения (скрытые зависимости между web и api).
- **Turborepo** — кэширование сборок полезно при многих пакетах; при двух приложениях это лишняя концепция.
- **`packages/shared-types`** — заменён генерацией типов из Swagger (ADR 0006).

## Последствия

- Каждое приложение объявляет свои зависимости; случайная зависимость web от пакетов api не соберётся.
- Добавление общего пакета — новый ADR с обоснованием.
