# Требования

> Источники: исходный Swagger ([API_INVENTORY.md](api/API_INVENTORY.md)) и согласованные с командой решения (2026-10-20).
> «Подтверждено» = функция есть в исходном Swagger **и** включена командой в объём. Детали поведения,
> которых нет в Swagger, помечены 📝 (предложено) или ❓ (вопрос, раздел 5).

## 1. Подтверждённые функциональные требования

Включены все модули исходного Swagger. Номера `#` — операции из API_INVENTORY.md.

### Account / Auth — [спецификация](features/auth.md)
- FR-AUTH-1. Регистрация: `userName`, `fullName`, `email`, пароль (#1).
- FR-AUTH-2. Вход по `userName` и паролю (#2); вход создаёт серверную сессию.
- FR-AUTH-3. Восстановление пароля по email: запрос ссылки (#3) и установка нового пароля по токену (#4).
- FR-AUTH-4. Смена пароля с подтверждением текущего (#5).
- FR-AUTH-5. Выход из аккаунта 📝 (нет в Swagger, необходим для сессий).

### User / UserProfile — [спецификация](features/users-and-profiles.md)
- FR-USER-1. Просмотр своего профиля (#53) и профиля другого пользователя (#51), включая признак «я подписан» (#52).
- FR-USER-2. Изменение «о себе» и пола (#54).
- FR-USER-3. Загрузка и удаление аватара (#56, #57).
- FR-USER-4. Поиск пользователей с пагинацией (#41) — по `userName`/`fullName`, **без поиска по email**.
- FR-USER-5. Удаление аккаунта (#50) — своего; удаление чужих — только администратором (Q6).
- FR-USER-6. Список избранных постов (#55).

### FollowingRelationShip — [спецификация](features/follows.md)
- FR-FOLLOW-1. Подписаться / отписаться (#14, #15).
- FR-FOLLOW-2. Списки подписчиков и подписок любого пользователя (#12, #13).

### Post — [посты](features/posts.md), [взаимодействия](features/post-interactions.md)
- FR-POST-1. Создание поста с изображениями и необязательными `title`/`content` (#26).
- FR-POST-2. Удаление своего поста (#27).
- FR-POST-3. Просмотр поста (#23), постов пользователя (#21, #24), общей ленты с поиском (#21).
- FR-POST-4. Лента постов из подписок (#25).
- FR-POST-5. Reels (#22) — требования в разделе 4.1.
- FR-POST-6. Лайк поста (#28), просмотр (#29), комментарий (#30), удаление комментария (#31), избранное (#32) — раздел 4.

### Story — [спецификация](features/stories.md)
- FR-STORY-1. Публикация сторис из изображения или из поста (#38).
- FR-STORY-2. Лента сторис (#33), сторис пользователя (#34) и свои (#35), просмотр одной (#37).
- FR-STORY-3. Удаление своей сторис (#39).
- FR-STORY-4. Отметка просмотра (#40) и лайк (#36); автор видит число просмотров и лайков (по `viewerDto`).

### Chat — [спецификация](features/chat.md)
- FR-CHAT-1. Список своих чатов (#6), открытие чата (#7), создание чата с пользователем (#8).
- FR-CHAT-2. Отправка сообщения с текстом и/или файлом (#9).
- FR-CHAT-3. Удаление своего сообщения (#10) и чата (#11).

### Search History — [спецификация](features/search-history.md)
- FR-SEARCH-1. История текстовых запросов: добавить, список, удалить одну, очистить (#42–#45).
- FR-SEARCH-2. История просмотренных в поиске пользователей: то же (#46–#49).

### Location — [спецификация](features/locations.md)
- FR-LOC-1. Справочник локаций: список с фильтрами и пагинацией, просмотр, создание, изменение, удаление (#16–#20).
  Назначение и права — Q20, Q6.

## 4. Требования к отдельным механикам

Всё в этом разделе — 📝 предложение, если не указан вопрос. Реализуется так, пока команда не решит иначе.

### 4.1 Reels (Q10)
- Reel — пост с **одним видео** (`isReel = true`); обычный пост — 1–10 изображений.
- `GET /reels` — только reels, новые сначала. Reels также видны в профиле автора и в ленте.
- Видео: MP4, ≤ 100 МБ; длительность не проверяется (нет обработки видео; требует ffprobe — позже).
- Транскодирования и превью-кадров нет (возможны с BullMQ в будущем).
- **Если видео не нужно (ответ на Q10)** — `get-reels` превращается в ленту постов с отметкой и реализуется минимально.

### 4.2 Срок жизни Stories (Q11)
- Сторис активна **24 часа** с момента публикации (`expiresAt = createdAt + 24h`).
- Истёкшие сторис не возвращаются API; физическое удаление файлов — позже (BullMQ) или при удалении автором.
- Архив своих истёкших сторис — нет (по умолчанию).
- Лента сторис: авторы, на которых я подписан, и я; сначала авторы с непросмотренными сторис.

### 4.3 Комментарии (Q13)
- Текст 1–1000 символов; без ответов на комментарии и без редактирования.
- Удалить может автор комментария и автор поста.
- Список — от старых к новым, постранично.

### 4.4 Лайки (Q15)
- Один лайк от пользователя на пост/сторис; явные «поставить» (`PUT`) и «снять» (`DELETE`), повтор безопасен.
- Можно лайкать свои посты. Число лайков видно всем; список лайкнувших — не реализуется (нет в Swagger).

### 4.5 Избранное
- Личный список: видит только владелец. Добавить/убрать — идемпотентно. Порядок — недавно добавленные сначала.

### 4.6 Просмотры (Q14)
- Пост: просмотр засчитывается один раз на пользователя; свои просмотры автора не считаются.
  Frontend отправляет `PUT /posts/{id}/view`, когда пост открыт или ≥ 50% поста видно в ленте ≥ 1 с.
- Сторис: просмотр — при показе сторис; автор видит число и список зрителей.

### 4.7 Сообщения (Q16–Q19, Q29)
- Только личные чаты 1:1; один чат на пару пользователей.
- Сообщение: текст ≤ 2000 символов и/или один файл; хотя бы одно из двух.
- Удаление своего сообщения — для обоих участников; удаление чата — для обоих (по умолчанию, Q16).
- Новые сообщения: обновление каждые ~5 с на открытом чате (polling) до решения Q19.
- Нельзя писать самому себе.

## 6. Явно исключено

- Групповые чаты, звонки, голосовые сообщения.
- Приватные аккаунты, блокировки, жалобы, модерация (Q22).
- Ответы на комментарии, упоминания (@), хэштеги.
- Редактирование постов, комментариев, сообщений (Q13, Q27).
- Транскодирование видео, фильтры и редактор изображений.
- Вход через Google/Facebook, двухфакторная аутентификация, подтверждение email.
- Рекомендательные алгоритмы: ленты сортируются по времени.
- Мобильные приложения (только адаптивный веб).
- Микросервисы.
