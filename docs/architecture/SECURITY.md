# Безопасность

> Статус: ✅ согласованы принципы. Числовые лимиты помечены 📝.
> HttpOnly cookie — **одна из** мер, а не вся защита. Ниже — полный набор.

## Модель угроз (кратко)

| Угроза | Основная защита |
|---|---|
| Кража пароля из БД | Argon2id |
| Кража сессии через XSS | HttpOnly cookie; React экранирует вывод; запрет `dangerouslySetInnerHTML` |
| Подделка запроса с чужого сайта (CSRF) | `SameSite=Lax` + проверка `Origin` |
| Доступ к чужим данным (IDOR) | проверка владения в каждом сервисе; чужие чаты → `404` |
| Изменение чужих полей (mass assignment) | `ValidationPipe` с `whitelist` + DTO с явными полями |
| Перебор паролей, спам | rate limiting |
| Вредоносные файлы | проверка типа по содержимому, лимиты, случайные имена, раздача с правильным `Content-Type` |
| Утечка секретов | `.env` в `.gitignore`, только `.env.example` в репозитории |
| Утечка данных в ошибках/логах | единый фильтр ошибок; логирование без секретов |

## Аутентификация и сессии

См. [AUTHENTICATION.md](AUTHENTICATION.md): серверные сессии, хеш токена в БД, сроки, отзыв при смене пароля.

## Авторизация

**Аутентификация** — «кто ты» (guard сессии). **Авторизация** — «можно ли тебе это» (проверка в сервисе).

Правила:

1. Все маршруты по умолчанию требуют сессию. Публичные — только с `@Public()` и только помеченные Public в
   [endpoints/auth.md](../api/endpoints/auth.md) (регистрация, код, вход, сброс пароля, OAuth) и `health`.
2. Идентификатор текущего пользователя — только из сессии (`@CurrentUser()`), никогда из тела или query.
3. Проверка владения — в сервисе, перед изменением: сначала найти ресурс, затем сравнить владельца.
4. Если пользователь не должен знать о ресурсе (чужой чат, сообщение) — `404`. Если ресурс публичный,
   но действие запрещено (удалить чужой пост) — `403`.
5. Ответы содержат только явно выбранные поля (Prisma `select`) — `passwordHash`, `email` других
   пользователей и служебные поля не попадают наружу.

6. **Приватность проверяется на каждой выдаче** через `VisibilityService` (модуль `privacy`): списки, ленты, поиск,
   комментарии, уведомления, события Socket.IO и раздача файлов используют одни и те же правила.

| Ресурс | Читать | Изменять/удалять |
|---|---|---|
| Шапка профиля, счётчики | любой вошедший, кроме блокировки в любую сторону (→ 404) | только владелец (`/me`) |
| Публикации, reels, отметки, списки подписок, актуальное | открытый аккаунт — все; закрытый — подписчики (`ACCEPTED`) и сам (→ `403 PRIVATE_ACCOUNT`) | автор |
| `email`, дата рождения, настройки, сессии | только сам | только сам |
| Комментарии | как пост; `isPendingApproval` — автор комментария и автор поста | автор комментария; удалить — ещё автор поста; закрепить — автор поста |
| Истории | как публикации + аудитория (`CLOSE_FRIENDS`) + «скрыть от» + срок 24 ч (кроме автора и актуального) | автор |
| Зрители, ответы на стикеры, лайки историй | автор | — |
| Число лайков | всем, если автор не скрыл; иначе только автору | — |
| Сохранённое, подборки, история поиска, архив, близкие друзья, блоки | только владелец | только владелец |
| Чат, сообщения, вложения, звонки | только участники (→ 404) | сообщение — автор; группа — администраторы |
| Места | любой вошедший | `ADMIN` |
| Жалобы | автор жалобы (своя), `ADMIN` | `ADMIN` |

**Блокировка** — в обе стороны: 404 на профиль и всё, что с ним связано; исчезновение из поиска, лент, комментариев,
списков, уведомлений, событий; запрет сообщений и звонков. **Ограничение** — его комментарии видны только ему,
сообщения — в запросах. **Скрытие** — влияет только на ленты скрывающего.

## Вход через Google и Facebook

- Authorization Code Flow с **PKCE** и случайным `state` в короткой HttpOnly-cookie (10 минут); `state` сверяется в callback.
- Google — проверка подписи и `aud` у `id_token`, `email_verified = true` обязательно для автоматической привязки.
- Facebook — email без гарантии подтверждения: автоматическая привязка к существующему аккаунту **не выполняется**,
  только явная привязка из настроек вошедшего пользователя 📝.
- Адреса возврата — фиксированный список у провайдера; параметр `redirect` после входа — только относительный путь.
- Секреты провайдеров — только в `apps/api/.env`.
Подробно — [ADR 0014](../decisions/0014-oauth-google-facebook.md).

## Реальное время и звонки

- Сокет аутентифицируется cookie сессии; `Origin` проверяется при рукопожатии; при выходе и отзыве сессии сокеты закрываются.
- Каждое событие от клиента (`chat:typing`, `call:signal`) проверяется: участник ли пользователь, не заблокирован ли он; ограничение частоты.
- WebRTC: звук и видео идут напрямую между браузерами (IP-адреса участников видны друг другу — как в любом P2P-звонке);
  учётные данные TURN — временные (≤ 1 час 📝), выдаются только вошедшим.

## CSRF

Сессия в cookie означает, что браузер приложит её к любому запросу на наш сайт — в том числе
инициированному чужой страницей. Защита из двух слоёв:

1. **`SameSite=Lax`** — браузер не отправляет cookie в межсайтовых `POST`/`PUT`/`PATCH`/`DELETE` и `fetch`.
2. **Проверка `Origin`** в NestJS для всех изменяющих методов: заголовок `Origin` должен быть равен
   `WEB_ORIGIN`; если его нет или он другой → `403 CSRF_REJECTED`. Дополнительно, если браузер прислал
   `Sec-Fetch-Site` и он не `same-origin` → тоже отказ.

Плюс правило: **`GET` никогда не изменяет данные**.

Почему без CSRF-токена: при одном origin, `SameSite=Lax` и строгой проверке `Origin` токен не добавляет
существенной защиты для этого проекта (подход описан в OWASP CSRF Cheat Sheet как допустимая защита
в глубину), а усложняет клиент. Если преподаватель потребует токен (Q1) — добавляется synchronizer token
в сессии и заголовок `X-CSRF-Token` в API-клиенте; остальная архитектура не меняется.

Вход и регистрация тоже защищены проверкой `Origin` (защита от «login CSRF»).

## CORS

Браузер обращается к API на том же origin, поэтому CORS **не включается**. NestJS не отвечает
заголовками `Access-Control-Allow-*`, и чужие сайты не могут читать ответы. Если в будущем API
понадобится вызывать с другого origin — явный список `WEB_ORIGIN`, `credentials: true`, отдельный ADR.

## Валидация запросов

- Один механизм на backend: `class-validator` в DTO + глобальный `ValidationPipe`
  (`whitelist`, `forbidNonWhitelisted`, `transform`).
- id в пути — `ParseUUIDPipe`; `limit` — целое 1..50; `cursor` — проверяемая непрозрачная строка (ADR 0017).
- Строки обрезаются по краям и ограничены по длине (лимиты — в спецификациях функций).
- Переменные окружения проверяются при старте; без обязательных переменных приложение не запускается.
- Frontend повторяет только простые проверки для удобства; источник истины — backend.

## Ограничение частоты запросов

`@nestjs/throttler`, хранилище в памяти процесса (одного экземпляра достаточно; при нескольких — Redis).

| Операция | Лимит 📝 | Ключ |
|---|---|---|
| `POST /auth/login` | 5 в минуту, 20 в час | IP + `login` |
| `POST /auth/register`, `/register/resend-code` | 5 в час | IP |
| `POST /auth/register/verify`, `/me/email/verify` | 5 попыток на код | код |
| `POST /auth/password/forgot` | 3 в час | IP + `login` |
| `POST /auth/password/reset`, `/change` | 5 в 15 минут | IP / пользователь |
| `PUT /me/username` | 2 за 14 дней 📝 | пользователь |
| `POST /media` | 100 в час | пользователь |
| `POST /posts`, `POST /stories` | 25 в час | пользователь |
| комментарии, сообщения | 60 в минуту | пользователь |
| подписки (`PUT /users/{id}/follow`) | 60 в час | пользователь |
| лайки | 300 в час | пользователь |
| `POST /reports` | 20 в час | пользователь |
| `chat:typing` (сокет) | 1 в 2 с на чат | пользователь |
| остальные запросы | 300 в минуту | пользователь или IP |

Ответ при превышении — `429 RATE_LIMITED` с `Retry-After`.

## Загрузка файлов

| Назначение | Типы 📝 | Размер 📝 | Количество |
|---|---|---|---|
| Публикация (`purpose=POST`) | изображения JPEG, PNG, WebP, HEIC; видео MP4, MOV, WebM | фото ≤ 30 МБ, видео ≤ 650 МБ, ≤ 60 мин 📝 | 1–20 на пост |
| Reel (`REEL`) | MP4, MOV, WebM | ≤ 650 МБ, ≤ 3 мин 📝 | 1 |
| История (`STORY`) | фото / видео | фото ≤ 30 МБ, видео ≤ 250 МБ, ≤ 60 с 📝 | 1 |
| Аватар (`AVATAR`) | JPEG, PNG, WebP | ≤ 10 МБ | 1 |
| Сообщение (`MESSAGE`) | фото / видео | как у публикации | до 10 на сообщение 📝 |
| Голосовое (`VOICE`) | WebM/Opus, MP4/AAC, OGG | ≤ 10 МБ, ≤ 60 с 📝 | 1 |
| Обложка актуального | JPEG, PNG, WebP | ≤ 10 МБ | 1 |

Правила:

1. Лимит размера применяется **во время приёма** (multer `limits`), а не после чтения файла целиком.
2. Тип определяется по **содержимому** (сигнатура файла), а не по расширению и не по заголовку клиента.
3. Имя файла в хранилище — случайный UUID; исходное имя не используется в пути (защита от path traversal).
4. Файлы отдаются только через `GET /media/{id}` с правильным `Content-Type`, `X-Content-Type-Options: nosniff`
   и `Content-Disposition` для не-медиа вложений. SVG и HTML не принимаются.
5. Вложения чата отдаются только участникам чата.
6. Удаление записи (пост, сторис, аватар, сообщение) удаляет и файл в хранилище.
7. EXIF (в т.ч. GPS-координаты) удаляется из всех изображений (`sharp`, ADR 0016); видео перекодируется ffmpeg —
   метаданные исходного файла не сохраняются. ffmpeg запускается с фиксированными аргументами, без пользовательских
   строк в командной строке, с ограничением времени.
8. Бакет R2/S3 в продакшене — **приватный**; доступ к файлам только через backend.

## Секреты и конфигурация

- В репозитории только `.env.example` с пустыми или явно фиктивными значениями.
- Реальные значения — в `.env` (локально) и в настройках среды развёртывания.
- Тестовые учётные данные для разработки — в `prisma/seed.ts` (только для локальной БД).
- При утечке секрета — замена секрета, а не просто удаление из истории Git.

## Ошибки и логирование

- Клиент получает только формат из контракта; stack trace и тексты SQL-ошибок — только в логах сервера.
- Ошибки Prisma переводятся в понятные коды (нарушение уникальности → `409 CONFLICT`, запись не найдена → `404`).
- В логи не пишутся пароли, токены, cookie, содержимое сообщений.
- Каждый запрос получает `requestId`; он есть в логе и в ответе с ошибкой.

## HTTP-заголовки

- NestJS: `helmet` с настройками по умолчанию (API не отдаёт HTML).
- Next.js: `Content-Security-Policy`, `X-Content-Type-Options`, `Referrer-Policy`, `frame-ancestors 'none'` —
  настраиваются в Phase 0, ужесточаются перед деплоем.
