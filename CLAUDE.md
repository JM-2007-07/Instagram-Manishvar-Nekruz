# CLAUDE.md — инструкции для Claude Code

Учебный экзаменационный проект двух студентов: Instagram-подобная соцсеть.
Монорепозиторий pnpm: `apps/web` (Next.js App Router) и `apps/api` (NestJS + Prisma + PostgreSQL).
Код должен быть понятен студенту и удобен для защиты перед преподавателем.

## Текущая фаза

Смотри [docs/ROADMAP.md](docs/ROADMAP.md). **Не начинай следующую фазу и не реализуй функции за её пределами
без явной просьбы пользователя.** Документирование фазы не означает разрешения на её реализацию.

## Перед любой задачей

1. Определи модуль и его владельца — [docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md#2-распределение-модулей).
   Спроси пользователя, кто он (Студент A или B), если это влияет на задачу.
2. Прочитай спецификацию функции в [docs/features/](docs/features/README.md).
3. Сверь эндпоинты с [docs/api/API_CONTRACT.md](docs/api/API_CONTRACT.md), данные — с [docs/database/DATA_MODEL.md](docs/database/DATA_MODEL.md).
4. Для архитектурных вопросов — [docs/architecture/](docs/architecture/ARCHITECTURE.md) и [docs/decisions/](docs/decisions/README.md).
5. Если задача упирается в открытый вопрос `Qn` из [REQUIREMENTS.md](docs/REQUIREMENTS.md#5-открытые-вопросы) или
   критичная информация отсутствует — **спроси**, не додумывай. Значение «по умолчанию» из таблицы вопросов
   можно использовать, только явно сказав об этом.

## Обязательные архитектурные правила

- Бизнес-логика, права доступа и работа с БД — **только в NestJS**. Next.js не дублирует бизнес-правила.
- Браузер обращается к API только через same-origin `/api/v1/...` (rewrite в Next.js). Нет `NEXT_PUBLIC_API_URL`.
- Один HTTP-клиент: `openapi-fetch` из `apps/web/src/lib/api`. Клиентское состояние сервера — только TanStack Query.
  Не добавляй axios, RTK Query, SWR, Redux, Zustand, Server Actions для изменений.
- Компоненты не вызывают API напрямую — только через `features/<name>/api.ts`.
- Типы API не пишутся вручную: генерируются `pnpm contract` из Swagger NestJS. Не редактируй
  `docs/api/openapi.json`, `apps/web/src/lib/api/schema.d.ts` и `docs/api/original-swagger.json`.
- Сессии: серверные, HttpOnly cookie. JavaScript никогда не читает и не хранит токен. Нет JWT в localStorage.
- Текущий пользователь — только из сессии (`@CurrentUser()`), никогда из тела или query.
- Каждый изменяющий endpoint проверяет права владения в сервисе; изменяющие операции — не `GET`.
- Валидация backend — `class-validator` в DTO с глобальным `ValidationPipe` (whitelist). Не добавляй вторую систему валидации на backend.
- Ошибки — единый формат из API_CONTRACT.md §1.2. Не возвращай stack trace и тексты SQL-ошибок.
- Prisma-схема и миграции — только в `apps/api/prisma`. Влитые миграции не редактируются.
- Не добавляй Redis, BullMQ, Socket.IO, Docker, новые пакеты в `packages/` без ADR и одобрения пользователя.

## Простота кода

- Стандартные соглашения NestJS (controller → service → DTO) и Next.js. Без репозиториев, use-case классов,
  фабрик, generic-обёрток «на будущее».
- Явные типы, понятные имена, небольшие файлы. Без сложных generic-типов.
- Комментарии — на русском или английском, только для неочевидных решений.
- Код, имена файлов, endpoint'ы, коммиты — на английском.
- Новая зависимость — только с обоснованием; сначала проверь, нельзя ли обойтись стандартными средствами.

## Общие файлы и границы модулей

- Работай только в файлах модуля текущей задачи. Список общих файлов — [CONTRIBUTING.md](CONTRIBUTING.md#общие-файлы).
- Перед изменением общего файла, `schema.prisma` или API-контракта — **остановись и предупреди пользователя**,
  что это затрагивает второго разработчика; следуй [CHANGE_PROCESS.md](docs/development/CHANGE_PROCESS.md).
- Изменил контракт → обнови `API_CONTRACT.md` и выполни `pnpm contract` в том же изменении.
- Изменил поведение → обнови спецификацию функции. Принял архитектурное решение → предложи ADR.
- Не оставляй документы противоречащими друг другу.

## Безопасность

- Не записывай секреты в код, документацию, логи, тестовые снимки. Только `.env.example` с фиктивными значениями.
- Пароли — Argon2id; токены сессий и сброса — в БД только хешем.
- Загрузки — лимиты размера, проверка типа по содержимому, случайные имена файлов.
- Подробно: [docs/architecture/SECURITY.md](docs/architecture/SECURITY.md).

## Проверка работы

- Перед завершением задачи: `pnpm lint`, `pnpm typecheck`, `pnpm test` (когда приложения существуют).
- Тесты — по [docs/development/TESTING.md](docs/development/TESTING.md): правила доступа и бизнес-правила обязательно.
- Никогда не сообщай об успешной проверке, которую не запускал. Если что-то не проверено — скажи об этом.
- Не коммить и не пушь без просьбы пользователя. Работа — в feature-ветке, не в `main`.
