# AGENTS.md — точка входа для ИИ-агентов

Этот файл читает **любой** ИИ-агент (Claude Code, Codex, Cursor, Copilot и др.) перед работой в репозитории.
Он короткий намеренно: здесь — что за проект, как ориентироваться и какие правила нельзя нарушать.
Детали — в документах, на которые он ссылается.

## 1. Проект за 30 секунд

- Учебный экзаменационный проект двух студентов: Instagram-подобная соцсеть.
- Монорепозиторий **npm workspaces**: `apps/web` (Next.js App Router, TypeScript, Tailwind, shadcn/ui, TanStack Query)
  и `apps/api` (NestJS, REST `/api/v1`, Swagger, Prisma, PostgreSQL).
- Сессии — серверные, в PostgreSQL, HttpOnly cookie. Браузер ходит в API через same-origin прокси Next.js.
- Главный критерий качества: **студент может объяснить любой файл преподавателю.** Простота важнее «правильных» абстракций.

## 4. Рабочий цикл агента

1. **Сориентируйся:** STATUS.md → какая задача (`Tx.y`) и кто её владелец (Студент A/B). Если пользователь
   не назвал задачу или роль, а это важно, — спроси.
2. **Проверь готовность** (Definition of Ready в [AGENT_PLAYBOOKS.md](docs/development/AGENT_PLAYBOOKS.md#definition-of-ready)):
   зависимости задачи выполнены, блокирующие вопросы `Q` закрыты или есть значение по умолчанию.
3. **Прочитай** спецификацию функции, раздел контракта, модель данных.
4. **Составь короткий план** и покажи пользователю, если задача больше нескольких файлов.
5. **Сделай** в пределах модуля задачи, по [CODING_CONVENTIONS.md](docs/development/CODING_CONVENTIONS.md).
6. **Проверь** командами из раздела 6. Не заявляй о проверке, которую не выполнял.
7. **Обнови документацию** в том же изменении: спецификация, контракт, STATUS.md (статус задачи) и **новая история**
   в `docs/stories/` ([правила и шаблон](docs/stories/README.md)) + строка в оглавлении STATUS.md §7.
8. **Передай дела:** итог для пользователя — что сделано, что не проверено, что дальше.

## 5. Правила, которые нельзя нарушать

**Объём**
- Не выходи за текущую фазу и задачу. Документирование фазы ≠ разрешение её реализовать.
- Не придумывай endpoint'ы, поля DTO и бизнес-правила, которых нет в документах. Неизвестное — спроси
  или используй значение «по умолчанию» из REQUIREMENTS §5, **явно сказав об этом**.

**Архитектура**
- Бизнес-логика, права и БД — только в NestJS. Next.js не дублирует бизнес-правила.
- Браузер ходит только в same-origin `/api/v1/...`. Нет `NEXT_PUBLIC_API_URL`.
- Один HTTP-клиент: `openapi-fetch` из `apps/web/src/lib/api`; серверное состояние — только TanStack Query.
  Не добавлять axios, RTK Query, SWR, Redux, Zustand, Server Actions для изменений.
- Компоненты не вызывают API напрямую — только через `features/<name>/api.ts`.
- Типы API генерируются (`npm run contract`). Не редактировать руками: `docs/api/openapi.json`,
  `apps/web/src/lib/api/schema.d.ts`, `docs/api/original-swagger.json`, влитые миграции Prisma.
- `apps/web` не импортирует из `apps/api` и наоборот.
- Не добавлять Redis, BullMQ, Socket.IO, Docker, пакеты в `packages/` без ADR и одобрения пользователя.

**Безопасность**
- Сессия — HttpOnly cookie; JavaScript не читает и не хранит токен. Текущий пользователь — только из `@CurrentUser()`.
- Каждое изменение данных проверяет права владельца в сервисе; изменения — не через `GET`.
- Никаких секретов в коде, документах, логах. Не читать и не выводить содержимое `.env`.

**Совместная работа**
- Общие файлы ([CONTRIBUTING.md](CONTRIBUTING.md#общие-файлы)), `schema.prisma` и API-контракт затрагивают второго
  разработчика: **остановись и предупреди пользователя**, затем следуй [CHANGE_PROCESS.md](docs/development/CHANGE_PROCESS.md).
- Завершённые логические шаги фиксируй **коммитами в текущей ветке** (Conventional Commits, см. CONTRIBUTING.md).
  Не создавай новую ветку на каждое изменение. Новые ветки, push и PR — только по просьбе пользователя.
  Не работай напрямую в `main`.

## 6. Команды

> ⚠️ Приложений пока нет — команды заработают после Phase 0 (см. STATUS.md). До этого проверяется только документация.

| Цель | Команда |
|---|---|
| установка | `npm install` (только из корня) |
| запуск обоих приложений | `npm run dev` |
| проверки перед завершением задачи | `npm run lint`, `npm run typecheck`, `npm run test` |
| e2e API | `npm run test:e2e -w api` |
| после изменения API | `npm run contract`, затем `npm run typecheck` |
| миграция | `npm exec -w api -- prisma migrate dev --name <name>` (по CHANGE_PROCESS.md) |
| зависимость в приложение | `npm install <pkg> -w web` / `-w api` |

## 7. Когда остановиться и спросить

- Задача требует ответа на открытый вопрос `Q`, у которого нет значения по умолчанию или оно явно не подходит.
- Нужно изменить общий файл, контракт, схему БД или чужой модуль.
- Документы противоречат друг другу или коду.
- Нужна новая зависимость или инфраструктура.
- Нужно удалить или переписать существующий код/документы, назначение которых непонятно.
